# PmVault extensions for KeePassXC

This is a fork of **KeePassXC 2.7.12** that adds three features the upstream
project does not provide. Everything else (KDBX4 storage, browser DOM fill,
Auto-Type, per-entry TOTP, YubiKey support code, etc.) is inherited unchanged
from upstream. All PmVault code lives in [`src/pmp/`](src/pmp) and is licensed
under the same **GPL v2/v3** as KeePassXC.

All configuration is stored inside the KDBX database **CustomData** under the
`PM:` prefix (and therefore travels with the database export/backup), while
secrets and audit data stay **outside** the database in per-user app storage.
Nothing is ever uploaded to any cloud.

## Added features

### 1. TOTP as a database-unlock second factor (2FA)

After the master key successfully decrypts the database, an enrolled database
additionally requires a manually entered 6-digit TOTP code.

* Google-Authenticator-compatible (RFC 6238, HMAC-SHA1, 6 digits, 30 s, ±1 step).
* The seed is generated by the app and shown as an `otpauth://` URI + QR code;
  the app **never reads codes from an authenticator app**.
* The seed is stored in a per-device AES-256-GCM vault (`twofa/<id>.vault`,
  DPAPI-bound on Windows), is **not** part of the database and **does not take
  part in the KDF**.
* Defences: one-time use with replay rejection, constant-time comparison,
  exponential back-off (2 s · 2^n, capped at 60 s), and a 15-minute hard lock
  after 10 failures.
* Code: `src/pmp/PmpTwoFactor.*`, gate wired into
  `src/gui/DatabaseOpenWidget.cpp`.

### 2. Local encrypted, tamper-evident audit log

* Fixed event/outcome/field/target enumeration. The recording API takes **no
  value-class parameters** — passwords, user names, codes, titles and URLs are
  never logged, only the field *type*.
* Each record is AES-256-GCM sealed with the previous chain link as AAD;
  `link = HMAC(chainKey, prevLink || sealed)` forms a hash chain, so deleting,
  reordering or altering a record breaks every following record.
* A separately sealed anchor pins the last sequence number and link, detecting
  tail truncation. Files: `audit/<id>.logx` + `<id>.anchor`, outside the
  database and never synced. 10 MB rotation (keeps 5 archives), 90-day
  retention.
* Wired to unlock/lock, password change, copy, browser fill, Auto-Type, sync
  and configuration change.
* Code: `src/pmp/PmpAuditLog.*`.

### 3. LAN mutual-TLS-1.3 two-way sync

* Disabled by default. Port **19532**, a single **30-second** accept window,
  LAN/loopback peers only.
* Each device has an ECDSA P-256 self-signed identity
  (`sync/identity.enc`, device-bound). Peers authenticate with **mutual client
  certificates**, trust is decided solely by SHA-256 **certificate-fingerprint
  pinning** (the system CA store is ignored), and the negotiated protocol must
  be **TLS 1.3**.
* Line-delimited JSON protocol:
  `HELLO → MANIFEST → WANT → ENTRIES → APPLIED → BYE`.
* Merge uses per-entry **vector clocks** and **tombstones**; concurrent edits
  default to **KeepBoth** (the remote side is saved as a “conflict copy”);
  DeleteWins only affects the concurrent delete-vs-edit case.
* Code: `src/pmp/PmpSync*.{h,cpp}`, `PmpIdentity.*`, `PmpSyncTypes.h`.

## Configuration model

Global settings live in database Metadata CustomData; entry-level overrides
live in entry CustomData; both use the `PM:` prefix. Effective values are
resolved entry-override → global → compiled default
(`src/pmp/PmpConfig.*`). Defaults include: clipboard self-clear 10 s, idle lock
300 s, browser fill requires confirmation even for a unique match / never
auto-submits / https+localhost only, Auto-Type hot-key Ctrl+Alt+A with an 8 ms
key delay and sequence `{USERNAME}{TAB}{PASSWORD}{ENTER}`, sync off / port
19532 / KeepBoth, audit retention 90 days / 10 MB.

## Building

### Linux (build gate)

```sh
sudo apt install g++ cmake ninja-build pkg-config \
  qtbase5-dev qttools5-dev qttools5-dev-tools libqt5svg5-dev \
  libbotan-2-dev libargon2-dev libminizip-dev libqrencode-dev zlib1g-dev
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release \
  -DKEEPASSXC_BUILD_TYPE=Release -DWITH_TESTS=OFF -DWITH_GUI_TESTS=OFF \
  -DWITH_XC_DOCS=OFF -DWITH_XC_BROWSER=ON -DWITH_XC_NETWORKING=OFF \
  -DWITH_XC_SSHAGENT=OFF -DWITH_XC_KEESHARE=OFF -DWITH_XC_YUBIKEY=OFF \
  -DWITH_XC_UPDATECHECK=OFF -DWITH_XC_X11=OFF
cmake --build build -j
```

### Windows portable package (MSYS2 MINGW64)

Use the provided GitHub Actions workflow `.github/workflows/pmp-windows.yml`
(push a `v*` tag or run it manually); it builds and uploads
`PmVault-windows-x64.zip`. To reproduce locally in an MSYS2 MINGW64 shell:

```sh
pacman -S --needed make mingw-w64-x86_64-{cmake,gcc,qt5-base,qt5-svg,qt5-tools,\
qt5-imageformats,libbotan,argon2,minizip,qrencode,zlib}
cmake -S . -B build -G "MSYS Makefiles" -DCMAKE_BUILD_TYPE=Release \
  -DKEEPASSXC_BUILD_TYPE=Release -DWITH_TESTS=OFF -DWITH_GUI_TESTS=OFF \
  -DWITH_XC_DOCS=OFF -DWITH_XC_BROWSER=ON -DWITH_XC_NETWORKING=OFF \
  -DWITH_XC_SSHAGENT=OFF -DWITH_XC_KEESHARE=OFF -DWITH_XC_YUBIKEY=OFF \
  -DWITH_XC_UPDATECHECK=OFF
cmake --build build -j
bash scripts/pmp_windows_package.sh   # gathers DLLs into build/pmp-pkg
```

The shipped Windows build is the standard Qt layout (`keepassxc.exe` plus its
DLLs, ~34 MB portable), not a single-file executable.

## Verification performed

On a Linux tool-chain the full project was configured, compiled, linked and
smoke-tested: `keepassx_core` and all three programs
(`keepassxc`, `keepassxc-cli`, `keepassxc-proxy`) link cleanly,
`keepassxc-cli --version` reports `2.7.12`, and the GUI starts with the PmVault
menu installed. The Windows package is produced by the Windows CI runner.
